## Receipt and approval procedure

1. An authorized CartIQ representative must accept a written document for a named export and provider. Verify rights to receive and normalize, retain history, perform internal analytics, train and evaluate, serve derived forecasts, and display observations. Confirm upstream retailer coverage, location granularity, recipient roles, original file and evidence rights, retention deadline and revocation or deletion process. Confirm access rights to historical point-in-time evidence. Do not infer permissions from the provider's technical contract.
2. Verify the existing Phase 1 mapping and create the exact observation retention grant for one listing and location. Set only the uses expressly allowed. At `/api/admin/price-acquisition/sources/{grantId}`, `PUT` the document reference, digest, named `sourceIdentity`, permitted uses, `scope` and `revocationConditions`, with `collectionAllowed=true` and `retentionAllowed=true` only after review. Provider, retailer, location, date window and retention deadline come from the immutable linked grant. Training and serving require a separate accepted V14 approval and cannot exceed the source authorization. Revoking the registry entry also revokes its retention grant and removes its observations. Registry shows the expiry or revocation state separately from intake decisions.
3. Preserve original bytes in the approved evidence vault only if the writing permits retention. Run a multipart `POST /api/admin/price-acquisition/batches` with `grantId`, `format=CSV` or `JSON`, and `file`. Preview is the default. `evidenceReference` is optional and requires `rawEvidenceAllowed`. The backend hashes the exact file bytes, handles them in memory under the upload limit, and never saves the raw price file. Review the safe row-number decisions. In a new request with the identical file, use `commit=true&reviewed=true` only when ready. Commit persists the digest, approved evidence pointer when allowed, and safe row outcomes. Quarantined payloads are discarded. Resubmitting the same hash under the same grant and evidence configuration returns saved row decisions and completes any rows left after an interruption. `GET /batches` lists recent receipts and `GET /batches/{id}` lists decisions, both under the same API prefix. Inactive grants hide the original-file pointer and revoke or scheduled expiry removes it. Safe audit outcomes and the digest remain available.
4. Review **Admin dashboard → Review dataset coverage**. Coverage excludes simulated legacy prices, gives observed counts, dates and scope, and reports whether shortlisted series have enough eligible days and consecutive holdout targets. The dashboard requires an admin account. Separate historical intake outcomes from current eligible records. Committed rejects are represented only by row numbers and disposition codes. Operators must also honor evidence retention/deletion outside the app.

Preview and commit from an authorized shell using a private API URL, an admin bearer obtained through the normal sign-in procedure, the approved grant ID and the evidence file path. Keep tokens and files out of transcripts. The preview path alone does not create a batch.

```powershell
$uri = "$env:CARTIQ_STAGING_API_ORIGIN/api/admin/price-acquisition/batches"
$headers = @{ Authorization = "Bearer $env:CARTIQ_STAGING_ADMIN_BEARER" }
$form = @{ grantId = $env:CARTIQ_DATA_GRANT_ID; format = 'CSV'; file = Get-Item -LiteralPath $env:CARTIQ_DATA_FILE }
Invoke-RestMethod -Uri $uri -Headers $headers -Method Post -Form $form
```

If the application rolls back to V14, suspend source-registry operations, historical intake and forecast serving until V15 returns. The older forecast reader uses CartIQ ingestion timestamps and does not apply V15 source availability evidence.

### File contract

Use UTF-8, up to 512 KiB and 500 data rows. Submit CSV with the header below, a JSON array, or a JSON object containing only `rows`. JSON ID and timestamp fields must be strings. `priceMinor` is a positive integer in INR paise. `mrpMinor` and `discountPercent` are optional. `stock` is `AVAILABLE`, `OUT_OF_STOCK` or `UNKNOWN`. Submit actual source `observedAt` in whole-second ISO 8601 UTC. `dataClass=SIMULATED` is excluded even in otherwise valid data; commit requires an explicit operator review of the actual genuine source. Do not map a commodity series to a retail SKU.

```text
dataClass,sourceRecordId,sourceEvidence,observedAt,variantId,retailer,locationId,retailerSku,pack,currency,priceMinor,stock
```

Optional fields `sourceAvailableAt` and `sourceAsOfEvidence` must be supplied together, backed by source evidence and allowed by `historicalAsOfAllowed`. The timestamp must be on or after the observation. Missing or later availability is not filled. The true CartIQ ingestion timestamp remains separate. Train only on days where the evidence establishes that the source observation was available that UTC day, or where CartIQ actually ingested it on that day.
